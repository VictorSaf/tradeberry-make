Clickable controls — one rule

Proposal for tradeBerry, nothing in the app changes yet. Every control below is live: hover, click, Tab through it. The columns force each state so they can be compared side by side.

Yellow means one thing: you can act here. At rest a control carries one small yellow cue. Hover adds a yellow tint, on / open / selected is a yellow fill with black content, keyboard focus is a 2px yellow ring, disabled is grey with no yellow at all. Warnings stop using yellow; sell red and buy green stay for orders and P&L.

Tokens

--ctlrest cue: text, chevron, 1px line
--ctl-hoverhover: 15% yellow tint
--ctl-onon, open, selected: fill
--ctl-inkblack text and ticks on the fill
--ctl-focuskeyboard: 2px ring, offset
--ctl-offdisabled: grey, never yellow
--alertwarnings (new, leaves yellow)
--dn / --upsell / buy, P&L only

Warnings leave yellow

Today --warn (#f5a524) and the accent (#e8b04a) are nearly the same colour, so a warning looks clickable and a control looks like a warning. Proposed: warnings move to orange --alert with an icon; the calendar's Medium impact follows.

What this avoids

  • Yellow frames on everything at rest. In a dense terminal fifty frames are noise and nothing stands out; one small cue per control is enough.
  • Yellow on data. Prices, values and labels stay white or grey; a yellow number would read as a button.
  • A different rule per screen. The rule is per control type, applied across the whole app in one step per type: tick boxes, then dropdowns, then groups, tabs, buttons, fields.
